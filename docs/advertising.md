These are vendor category filters, not an independent guarantee about every future creative; report inappropriate creatives to Adsterra with the affected unit and evidence.

The homepage has two responsive display banners: after latest notices and before home mock listings. Topic reading pages, exam hubs and mock listings have an earlier banner and a page-end banner. Long guides and update articles retain one rectangle after their second section and one responsive page-end banner. Other permitted reading pages have one page-end banner. Embedded lesson pages use their quiz placement as the second slot rather than adding a third footer ad.

Calculators have two low-height responsive banners around the calculator, outside its inputs and outputs. Topic, daily and monthly current-affairs quizzes have one banner after the complete quiz card, with no ad inserted between questions or answer controls. That placement remains mounted when moving between questions; there is no question-triggered refresh. Mock tests have exactly one banner in the result component, after the score summary and before section analysis. The intro and active timed mock never mount an ad. Account pages, forms, typing tests and personal revision tools remain excluded.

There is no in-page hide or dismissal button, and the previous session-storage preference is no longer read. Fixed sizes are chosen from actual container width; containers narrower than 320px omit responsive units that cannot fit. Ads load near the viewport after browser idle, once per placement, without automatic refresh. Resizing never creates extra impressions for an already selected unit. No popup, popunder, Smartlink, Social Bar, sticky or interstitial integration is installed. Existing inactive formats in the account were left as they were.

`src/lib/adsterra.ts` holds the serving switch, confirmation timestamp, start time and route/size rules. `scripts/generate-ad-documents.mjs` generates the fixed-unit document. Vendor code executes only in `examshortcut.pages.dev/advertising/display`, framed by the production domain with no top-navigation, modal, form, download or autoplay permission. It cannot access the production application's DOM or account storage. The helper has noindex and an exact parent-origin allowlist. Application pages retain their existing frame protections.

Validation: `node --experimental-strip-types --test scripts/test-adsterra.mjs`; `npm run build` includes those checks, document generation and `verify-ad-export.mjs`. Do not add guessed ads.txt seller records; use only lines actually supplied for this account by the vendor.

Compare revenue per 1,000 pageviews, viewability, page speed and reader engagement before increasing density. More banners do not establish a revenue increase. Payment information in Adsterra requires the owner's review separately from this code integration.
